TCP وUDP: كيف تنتقل البيانات؟

شرح عربي متدرج مع رسوم توضيحية، وأمثلة حقيقية، وتطبيق عملي آمن، واختبار 20 سؤالًا.

المستوى: مبتدئ ← متوسطالمدة: 80–110 دقيقة20 سؤال اختيار من متعدد

1. ما هما TCP وUDP؟

عندما ترسل رسالة أو تفتح موقعًا، لا يكفي معرفة عنوان IP؛ نحتاج أيضًا إلى طريقة لنقل البيانات بين التطبيقات. هنا يأتي دور بروتوكولي TCP (Transmission Control Protocol) وUDP (User Datagram Protocol) في طبقة النقل Transport Layer.

تشبيه: TCP يشبه إرسال طرد مع تأكيد الاستلام وإعادة الإرسال عند الفقد، أما UDP فيشبه بث معلومات متتابعة دون انتظار تأكيد لكل رسالة. التشبيه للتوضيح وليس وصفًا حرفيًا لكل التطبيقات.

2. المنافذ Ports

عنوان IP يحدد الجهاز، ورقم المنفذ Port يساعد على تحديد الخدمة داخل الجهاز. تتراوح أرقام المنافذ من 0 إلى 65535، ولكل من TCP وUDP مساحة منافذ مستقلة.

الخدمةالمنفذ الشائعالبروتوكول

مثال: 192.0.2.10:443 يعني عنوان الجهاز والمنفذ المقصود. عنوان 192.0.2.10 مخصص للأمثلة التعليمية.

3. كيف يعمل TCP؟

قبل تبادل بيانات التطبيق، ينشئ TCP اتصالًا عبر Three-way Handshake:

العميل
Client
① SYN →
② ← SYN-ACK
③ ACK →
الخادم
Server

بعد الاتصال يستخدم TCP أرقام تسلسل Sequence Numbers وتأكيدات ACK وإعادة إرسال Retransmission عند الحاجة، إضافة إلى التحكم بالتدفق Flow Control والتحكم بالازدحام Congestion Control.

مهم: TCP يضمن تسليم تدفق البايتات بالترتيب إلى التطبيق ما دام الاتصال سليمًا؛ لكنه لا يضمن نجاح العملية التجارية أو وصول الرسالة إلى المستخدم النهائي.

4. كيف يعمل UDP؟

UDP بروتوكول بسيط لا ينشئ اتصالًا بالمصافحة الثلاثية ولا يوفر بنفسه تأكيد استلام أو ترتيبًا أو إعادة إرسال. كل وحدة بيانات تسمى Datagram.

6. أمثلة من الواقع

تصفح المواقع: يستخدم HTTP/1.1 وHTTP/2 بروتوكول TCP عادة، بينما يستخدم HTTP/3 بروتوكول QUIC فوق UDP.

الألعاب المباشرة: تستخدم كثير من الألعاب UDP لتحديث المواقع والحركات بسرعة، وقد تضيف موثوقية للأحداث المهمة.

تحميل الملفات: تحتاج التطبيقات إلى سلامة البيانات؛ ويمكن توفيرها عبر TCP أو عبر بروتوكول تطبيقي موثوق مبني فوق UDP.

DNS: غالبًا يبدأ استعلام DNS التقليدي عبر UDP، وقد يستخدم TCP بحسب الحالة.

7. TCP وUDP في الأمن السيبراني

في تحليل حركة الشبكة Traffic Analysis، تساعدك معرفة البروتوكول والمنافذ والحالة على فهم الاتصالات الطبيعية والمريبة.

ملاحظةتفسير محتملما الذي تتحقق منه؟
عدد كبير من SYN دون إكمال الاتصالضغط على الخدمة أو SYN flood محتملالمعدل والمصدر وسجلات الخادم
حركة UDP كثيفةبث مشروع أو إساءة استخدام محتملةالوجهة والمنفذ والحجم والسياق
اتصال بمنفذ غير معتادخدمة مخصصة أو نشاط مريبالعملية المالكة للمنفذ والتصريح
قاعدة مهمة: المنفذ وحده لا يثبت نوع التطبيق أو وجود هجوم؛ يجب تحليل السياق. ولا تفحص أجهزة أو شبكات لا تملكها أو ليس لديك إذن صريح بفحصها.

8. تطبيق عملي آمن على جهازك

افتح الطرفية على جهازك فقط. الأوامر التالية للعرض والفحص المحلي، ولا تحتاج إلى صلاحيات إدارية في المعتاد.

Windows — Command Prompt

netstat -ano
netstat -an -p tcp
netstat -an -p udp

لاحظ عمود Local Address وForeign Address وحالة TCP مثل LISTENING وESTABLISHED. يظهر PID لتحديد العملية.

Linux — Terminal

ss -tuln
ss -tan
ss -uan

الخيار -t لـ TCP و-u لـ UDP و-l للمستمع و-n لعرض الأرقام.

تجربة إضافية: المتصفح

افتح أدوات المطور في المتصفح ثم Network وتحقق من عمود Protocol إن كان ظاهرًا؛ قد ترى h2 (HTTP/2) أو h3 (HTTP/3).

سجل ملاحظتك: اختر منفذًا واحدًا ظهر في جهازك، واكتب رقم المنفذ والبروتوكول والحالة، ثم فكر: ما التطبيق الذي قد يستخدمه؟

9. تشخيص الأعطال

عند تعطل تطبيق، اسأل بالترتيب: هل الجهاز متصل بالشبكة؟ هل يعمل DNS؟ هل المنفذ صحيح؟ هل الخدمة تستمع؟ هل يمنع جدار الحماية الاتصال؟ هل المشكلة فقد حزم أو تأخير؟
