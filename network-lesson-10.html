🔧 استكشاف أخطاء الشبكات وإصلاحها

Network Troubleshooting: تعلّم كيف تشخّص مشكلات الاتصال، وتحدد أسباب الأعطال باستخدام أدوات النظام، وتختار الحل المناسب بناءً على الأدلة.

المستوى: مبتدئ إلى متوسط · الاختبار: 10 أسئلة · النجاح: 80%

1. ما المقصود بـ Network Troubleshooting؟

استكشاف أخطاء الشبكات هو عملية منهجية لتحديد أسباب مشكلات الاتصال والأداء، ثم اختبار الحلول والتحقق من عودة الخدمة للعمل بصورة صحيحة.

من أمثلة المشكلات:

  • الجهاز متصل بالشبكة لكنه لا يستطيع فتح المواقع.
  • تعذّر الوصول إلى جهاز داخل الشبكة المحلية.
  • بطء نقل البيانات أو انقطاع الاتصال بصورة متكررة.
  • فشل الحصول على عنوان IP.
  • تعذّر الوصول إلى خدمة محددة رغم عمل الإنترنت.
قاعدة مهمة: لا تبدأ بتغيير الإعدادات عشوائيًا. اجمع المعلومات أولًا، ثم اختبر فرضية واحدة في كل مرة.

2. منهجية حل مشكلات الشبكات

  1. Identify: تحديد المشكلة والأجهزة المتأثرة ووقت بدايتها.
  2. Establish a Theory: وضع فرضية لسبب العطل.
  3. Test: اختبار الفرضية باستخدام أدوات مناسبة.
  4. Plan: وضع خطة إصلاح وتقييم أثرها.
  5. Implement: تنفيذ الحل المصرح به.
  6. Verify: التأكد من عودة الخدمة وعدم ظهور آثار جانبية.
  7. Document: توثيق المشكلة والسبب والحل.

تساعد هذه المنهجية في تجنب إضاعة الوقت وتكرار الأخطاء.

3. فحص الاتصال باستخدام Ping

تُستخدم أداة Ping لإرسال رسائل ICMP Echo Request والتحقق من وصول ردود Echo Reply، عندما تسمح الأجهزة والشبكات بهذه الرسائل.

مثال على Windows أو Linux

ping 192.168.1.1

إذا وصل الرد، فهذا مؤشر على وجود اتصال IP بالوجهة، لكنه لا يضمن أن جميع التطبيقات والخدمات تعمل.

النتيجةتفسير محتمل
Replyاستجابة من الوجهة
Request timed outلم يصل رد خلال المهلة
Destination host unreachableتعذر الوصول إلى الوجهة وفق معلومات الشبكة المتاحة
فشل Ping لا يعني بالضرورة أن الجهاز متوقف؛ فقد تكون رسائل ICMP محظورة.

4. فحص إعدادات IP

يحتاج الجهاز عادة إلى عنوان IP وقناع شبكة، وقد يحتاج إلى بوابة افتراضية وخوادم DNS بحسب نوع الاتصال.

Windows

ipconfig /all

Linux

ip addr
ip route
مثال: 
IP Address:      192.168.1.20
Subnet Mask:     255.255.255.0
Default Gateway: 192.168.1.1
DNS Server:      1.1.1.1

تحقق من أن عنوان IP والبوابة الافتراضية يتوافقان مع إعدادات الشبكة الفعلية.

5. مشكلة DHCP وعنوان APIPA

إذا كان جهاز Windows مضبوطًا للحصول على عنوان IPv4 تلقائيًا ولم يحصل على عنوان من DHCP، فقد يختار عنوانًا ذاتيًا ضمن النطاق 169.254.0.0/16 باستخدام APIPA.

IPv4 Address: 169.254.25.18
Subnet Mask:  255.255.0.0

هذا قد يشير إلى تعذّر الحصول على عنوان من DHCP، لكنه ليس دليلًا قاطعًا على تعطل خادم DHCP نفسه.

افحص اتصال الجهاز بالشبكة، وإعدادات VLAN، وتوافر خادم DHCP، ثم جرّب تجديد العنوان عند الحاجة.

Windows

ipconfig /release
ipconfig /renew
قد تؤدي أوامر تجديد العنوان إلى قطع الاتصال مؤقتًا؛ لا تنفذها على جهاز تديره عن بُعد دون خطة مناسبة.

6. تشخيص مشكلات DNS

DNS يحوّل أسماء النطاقات إلى عناوين IP. إذا كان الاتصال بعناوين IP يعمل لكن الوصول إلى المواقع بأسمائها يفشل، فقد توجد مشكلة في DNS.

Windows

nslookup example.com

Linux

nslookup example.com

يمكن أيضًا الاستعلام من خادم محدد:

nslookup example.com 1.1.1.1
سيناريو: يستطيع المستخدم الوصول إلى عنوان IP لخادم، لكنه لا يستطيع الوصول إليه باسمه. افحص إعدادات DNS والسجلات المطلوبة قبل تغيير أي إعدادات.

7. تتبع المسار باستخدام Traceroute

تساعد أدوات تتبع المسار في استكشاف الموجّهات أو القفزات التي تمر عبرها حزم الفحص نحو الوجهة.

Windows

tracert 8.8.8.8

Linux

traceroute 8.8.8.8

قد تحتاج إلى تثبيت traceroute على بعض توزيعات Linux.

تعتمد هذه الأدوات على قيمة TTL أو Hop Limit ورسائل الشبكة المرتبطة بها.

قد لا تظهر جميع القفزات، وقد تختلف مسارات الفحص عن مسارات حركة التطبيقات. ظهور * لا يثبت وحده وجود عطل.

8. تشخيص مشكلات Routing وVLAN

قد تكون إعدادات IP صحيحة، لكن الجهاز لا يستطيع الوصول إلى شبكة أخرى بسبب مشكلة في التوجيه أو تقسيم الشبكة.

سيناريو: 
PC1: 192.168.10.10/24
VLAN 10

PC2: 192.168.20.10/24
VLAN 20

إذا لم يوجد Inter-VLAN Routing، فلن يتمكن الجهازان عادة من التواصل عبر الطبقة الثالثة.

عند التشخيص افحص:

  • VLAN المخصصة لكل منفذ.
  • حالة روابط Trunk وVLAN المسموحة عليها.
  • البوابات الافتراضية للأجهزة.
  • جداول التوجيه.
  • قواعد ACL وجدران الحماية.

9. تشخيص البطء وفقدان الحزم

قد ينتج ضعف الأداء عن ازدحام الشبكة أو مشكلات في الوصلات أو أخطاء الواجهات أو قيود الخادم أو التطبيق.

من المؤشرات المهمة:

  • Latency: زمن التأخير.
  • Packet Loss: نسبة الحزم المفقودة.
  • Jitter: تفاوت زمن وصول الحزم.
  • Throughput: معدل نقل البيانات الفعلي.
العرضاحتمال يحتاج إلى فحص
بطء جميع التطبيقاتازدحام أو مشكلة في الاتصال
بطء تطبيق واحدالخادم أو التطبيق أو مساره
انقطاع متكرروصلة غير مستقرة أو مشكلات لاسلكية
تأخر المكالماتLatency أو Jitter أو Packet Loss

10. مختبر تطبيقي: حل مشكلة اتصال

نفّذ التمرين التالي على جهازك أو داخل مختبر افتراضي تملك صلاحية استخدامه.

الحالة: جهاز موظف متصل بالشبكة، لكنه لا يستطيع فتح موقع داخلي للشركة.
  1. تحقق من اتصال كابل الشبكة أو Wi-Fi.
  2. اعرض إعدادات IP والبوابة الافتراضية.
  3. اختبر الاتصال بالبوابة باستخدام Ping.
  4. تحقق من حل اسم الموقع باستخدام nslookup.
  5. افحص المسار باستخدام tracert أو traceroute عند الحاجة.
  6. راجع ما إذا كانت الخدمة المطلوبة تعمل على المنفذ المناسب.
  7. تحقق من سياسات Firewall أو ACL إذا كانت لديك الصلاحية.
  8. حدد السبب الأكثر احتمالًا بناءً على النتائج.
  9. اختبر الحل المصرح به.
  10. وثّق المشكلة والإجراءات والنتيجة النهائية.

يمكن استخدام Cisco Packet Tracer لبناء سيناريوهات افتراضية تشمل IP وVLAN وRouting وDHCP.
